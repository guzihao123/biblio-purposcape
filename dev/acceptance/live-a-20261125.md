### 8.2 能否区分 OpenAlex / 模型抽取 / DB 写回

**当前不能区分。** 原因如下：

1. `backend/app/remote_stage.py:143-165` 在 worker 起点写入 started 后，使用 `NullReporter`，代码明确说明远端存储暂无增量 progress action。
2. `backend/app/orchestration.py:467-536` 的检索内部顺序为：OpenAlex 检索 → 模型分类/因素/关系抽取 → 统计 → 图谱 → 制品上传；这些阶段不会逐项写入任务 progress。
3. checkpoint 只在 `service(task, stage_input)` 完整返回后创建，见 `backend/app/remote_stage.py:169-180`。两个任务 checkpoint 都是 `null`，只能说明“整个 search service 未正常返回”，不能说明具体卡在哪一步。
4. 普通服务异常会走 `backend/app/remote_stage.py:190-205` 并调用 `_fail_started`。两任务在约一小时里保持 started，最后才由恢复机制判错，因此“普通异常已被捕获并写回 failed”这一路径缺乏证据；worker 挂起、进程被杀/重启、或 `complete_stage` / `fail_stage` 写回自身卡住仍属待验证假设。
