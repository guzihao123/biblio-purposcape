# 模板 D · 组会汇报 PPT 骨架（主题调研型，交付形式选「展示 PPT」时专用）

用法：模式 D + 交付形式选「展示 PPT」时，复制到输出目录作 PPT 页序提纲（outline.md 附），20–30 页、30–40 分钟。`调研初稿.md` 按 `D_主题调研骨架.md` 出九段正文；PPT 是其调研型汇报投影，不是把正文逐页搬上去。每页要点带 [n]；文献事实、调研者归纳、未来设想分别标为文献结论、[n] 支撑的“分析”、以及“设想”，不得混写。

**页面标题纪律（2026-11-23 用户指定）**：标题尽量表达本页结论，不只写“研究现状”“方法分析”等宽泛栏目名；栏目可放眉题。标题中的文献结论挂 [n]，归纳判断标“分析”，不得为凑结论句编造事实。

## 生产顺序（资产先行，硬性）

1. 先产出各部分的强制内容构件，再列逐页目录；每页只承担一个核心观点。
2. **先准备图表资产，再生成页面**：建立 `ppt_asset_manifest.json`，逐页登记 `page / kind(image|chart|diagram) / name / source / expected_text / degraded / reason / attempt_log`。趋势、分布、技术路线、方法框架、论文原图不能只写在“推荐图表形式”栏里。
3. 图表、图片和图形已经取得或完成图形设计后才写 PageSpec；页面中不得用“完整图见仪表盘”“此处放图”“待补图”冒充已交付图表。
4. 生成后同时跑文字证据核验、PPT 结构与图表核验、版式轮转与真实渲染抽查；任何一项失败都先返工。

## 取料总表（各节从既有产物取料，不新写综述散文）

| 节 | 内容与图表来源 |
|---|---|
| 背景与主题 | 方向原文 + 主题概念/内涵 + 现实需求 + 核心科学问题；概念框架使用真实研究链条绘制 |
| 检索策略与概况 | search_log.md（实际检索源/关键词/完整检索式/年限/筛选/剔除/池规模）+ stats_year.json + stats_topics_all.json |
| 研究进展 | 第 5 步方向堆（3–6 堆，每堆研究问题/思路/代表作/成果/局限）+ 时间轴或方向矩阵 |
| 核心方法与技术路线 | ⑥方法树 + 方法对比表 + 精读页技术实现；整体关系图、输入输出与模型架构 |
| 代表作精读 | 调研初稿精读页（3–5 篇，每篇 1–2 页）+ OA/用户自有 PDF 的原始技术框架图与实验结果图 |
| 不足与趋势 | 五角度不足 + 已解决/争议/未充分/新技术/新方向 + “不足→潜在突破”路径图 |
| 总结与讨论 | 3 发现 + 最重要趋势 + 2–3 科学问题 + 1–2 个优先方向 + 下一步建议 + 团队讨论 |

## 页序（第 1/2/3/4/5/6/8 部分；不单设第七部分）

0. **封面 + 目录**（2 页）：主题 / 模式 D / 日期 / 真实池规模；目录只列第 1/2/3/4/5/6/8 部分与参考文献。
1. **研究背景与主题介绍**（1–2 页）：现实需求与重要性；主题概念及内涵；核心科学问题；本次调研目的和范围。至少 1 张主题概念框架图，清楚区分“研究对象—作用链条—结局”。
2. **文献检索策略与研究概况**（3 页）：
   - 检索策略页：实际数据库、核心与扩展关键词、**完整检索式或字段与过滤条件**、年限、筛选标准、最终纳入篇数；数量必须可对回 search_log。
   - 年度趋势页：本页直接嵌入 stats_year 真实趋势图，标注当前年是否仍在累积；不得只放仪表盘链接。
   - 主题分布页：本页直接嵌入 stats_topics 真实分布图，给前 2–3 主题及占比；池内结构、国内外或机构信息不得挤占主图。
3. **国内外研究进展**（3–5 页）：按研究问题/技术路线分 3–6 方向，不按作者/年份逐篇罗列。每方向显式回答：主要研究问题 / 研究思路 / 代表作 [n] / 主要成果 / 现有局限；至少使用时间轴、方向矩阵或成果对比图之一。国内外对比以池内 countries/institutions 统计为准并注明覆盖边界。
4. **核心方法与技术路线**（4–6 页）：选 3–5 种代表方法，逐一讲基本原理 / 模型架构 / 输入输出 / 核心技术 / 优势 / 局限 / 适用场景。必须有：①不同方法整体关系或技术路线图；②关键方法的模型架构或输入输出图；③末页方法对比表。摘要没有的架构细节标【待核实】或不写，不能编图冒充原模型。
5. **代表性论文深度解读**（3–6 页）：精读 3–5 篇，每篇 1–2 页，统一 10 项：研究问题 / 研究动机 / 核心方法 / 技术实现 / 数据来源 / 实验设置 / 主要结果 / 创新点 / 局限 / 团队启发。优先展示原始技术框架图与关键实验结果图，图注为“[n] Fig.k，原文 pX，实际版本”。十项字段用紧凑矩阵或拆页，避免大段文字。
6. **现有研究不足与发展趋势**（2 页）：
   - 不足五角度：理论 / 方法 / 数据 / 机制 / 应用，每条尽量挂 [n]；池内未见的判断标“分析”，不写无证据不足。
   - 趋势页：明确哪些已较好解决 / 仍有争议 / 尚未充分研究 / 哪些新技术可能突破 / 可能形成哪些新方向，并以“现有不足→潜在突破”路径图收束。
8. **总结与讨论**（2–3 页）：3 个主要发现 + 最重要趋势 + 2–3 个最值得关注科学问题 + **1–2 个优先推荐方向 + 下一步研究建议** + 组会讨论问题。**不单设第七部分不等于删除第八部分的优先方向与下一步建议**；优先方向在此嵌入总结，不另做“潜在研究选题与推荐”章节。
9. **参考文献**（1–2 页）：GB/T 7714，编号与正文 [n] 一致；C 级/无摘要可列不可被引；撤稿不得出现。

## 图表资产与阅读深度（2026-11-23 修订）

- **年度趋势与主题分布为必备图**，不能因摘要级调研或全文未授权而降级；可直接使用真实聚合数据生成原生图表，或嵌入已生成的静态图。
- **原文图获取与全文精读解耦**：用户要求组会 PPT 展示论文原图，即触发对精读 3–5 篇的 OA 定位与相关页/图读取。只读摘要及相关图页时标“摘要＋原文图”，不得标“已读全文”；通读全文后才标“已读全文”及实际版本。全文独有方法细节仍须实际读全文，不能由图片猜出。
- **先尝试、后降级**：每篇精读论文都要记录 OA 定位、下载、图页定位与裁切结果。只有实际尝试失败，才允许在 manifest 写 `degraded:true + reason + attempt_log`，页面给 OA 链接与文字说明；“未授权全文”“默认摘要级”本身不再是直接跳过原图获取的理由。
- 降级页不被算作“已交付原文图”；可允许单篇降级，但不得让整份 PPT 回到零图片、零图表。开放获取或用户自有 PDF 均可用，不绕过付费墙。
- 自绘概念图、技术路线图与“不足→突破”路径图属于调研者归纳，标“分析”；不得重绘后冒充论文原图。原生图表、嵌入图片与自绘图形在 manifest 分开登记。

## 文件命名（硬性）

生成的 PPT 一律命名为 **`<主题>组会汇报.pptx`**：主题 = 第 1 步研究方向原文（去空白与 `/ : * ? " < > |` 等非法字符，超 24 个汉字截到 24 字），后接「组会汇报」四字，不加日期/模式/页数后缀。

## 核验口径

- `调研初稿.md`：`verify_delivery.py 调研初稿.md 3000-6000 --mode D`。
- PPT 抽取文本：`pptx_to_text.py <主题>组会汇报.pptx --out 汇报文本.md`，再跑 `verify_delivery.py 汇报文本.md 1500-4000`，报告另存 `verify_report_ppt.txt`。
- **PPT 结构与图表**：复制 `verify_ppt_delivery.py` 到输出目录，运行 `python3 verify_ppt_delivery.py <主题>组会汇报.pptx --manifest ppt_asset_manifest.json --out verify_ppt_report.txt`。页数、七部分内容、第八部分优先方向与下一步、指定图片/图表/框架图、降级获取记录均须通过。
- 版式：`check_layout_rotation.py slides/layout_manifest.json` 必须 exit 0；`check_deck` 的几何通过不能替代结构、图表与视觉验收。
- 真实渲染：抽查封面、趋势图页、方法对比页、至少一张精读原图页和总结建议页；无视觉能力时用 OCR 与元素/资源核验辅助，不能把“文件已生成”说成“视觉已通过”。
- 检索统计数字属结构性数字，在 conformance 披露；原文图、实际版本与降级项在 conformance 逐篇对账。

## 版式轮转（2026-11-22 用户反馈"版面单一"后增，PPT 必用）

**执行方式（硬要求，不是建议）**：不要手写 `card()`/`wide_card()` 从零搭，用 `{skill_dir}/scripts/pptx_layouts.py`——13 个版式族已按下表实现好，`Deck` 负责编号写盘并输出 `layout_manifest.json`；生成后必须跑 `check_layout_rotation.py`，**exit 1 就换版式重跑**。下表的"同类不连续超过 2 页"由该脚本机械判定，不靠自觉。

```python
deck = Deck(out_dir='slides', total=28, kicker='组会主题调研',
            sections={2: '目录', 3: '一 · 研究背景'}, source='来源：…')
deck.add_cover(title=…, subtitle=…, date=…, stats=[(真实数字, 标签), …], foot_lines=[…, …])
deck.add(2, '汇报结构', toc('结构导航', rows, '框架', note_lines))
deck.add(3, '研究背景', asym('临床需求', ll, '边界', rl, dark='left'))
deck.write()
# python3 {skill_dir}/scripts/check_layout_rotation.py slides/layout_manifest.json
```

同一个骨架连续翻页最容易"AI 味 + 单调"。按页面语义分配版式族，**同类版式不连续超过 2 页**，深浅/左右/上下要交替：

| 页面语义 | 版式族 | 要点 |
|---|---|---|
| 封面 | 左标题 + 右侧出血深色面板 | 深色块贴页边，面板内放 2–3 个真实统计数字，底部信息与标题上下呼应 |
| 目录 | 竖排编号行 | 01–04 + 1px 细分隔线，末尾一条说明条 |
| 单点数据 | 大数字 KPI | 60pt 级数字放深块（`FS_HERO`），右侧说明卡承载口径与判断 |
| 流程/步骤（检索路径、方法路线） | 编号方块 + 箭头 + 说明条 | 3–4 块；说明条在方块下方/上方交替，避免连续 4 页同形 |
| 结构化对比 | 表格 | 深色表头 + 斑马纹，首列加粗 |
| 代表作精读 | 左图右卡 / 左卡右图 | 原图与机制卡等高；图左右交替 |
| 两堆并置且行数相等 | 左右非对称双卡 | 深/浅对比，深色左右交替；行数不等会留下空卡（见下） |
| 两段递进 | 上下分区横带 | 整幅宽卡，深色顶/浅色顶交替 |
| 要点 + 结论 | 分隔线清单 + 结论卡 | 左裸清单（1px 线分隔）+ 右浅底结论卡 |
| 5 点以上清单 | 编号清单 | 编号胶囊 + 行间 4–6px 呼吸；22pt 下**最多 6 条**，7 条起拆页 |
| 总结页 | 三栏发现卡 + 判断条 | 每条发现一卡，底部一句判断 |
| 参考文献 | 双栏列表 | 每栏 **3 条**（18pt 下 4 条会贴边），多出的拆第二张文献页 |

硬规则：
1. **卡片高度由内容决定**（同排用 `alignItems: 'stretch'` 等高），不要给卡片写死 420–460 高——文字只占上半时就是"框中浮字"；内容区整体垂直居中，留白才像设计而非未完成。
2. **字号（2026-11-23 用户修订，硬性）**：页标题统一 **30pt**（含封面主标题，不分页面类型）；正文要点、卡片内文字、结论条、以及页标题上方那行眉题（栏目小字）统一 **22pt**；卡片/小节标题 **27pt**；页码/来源/图注 **13.5pt**；表格 **16.5pt**；参考文献条目 **13.5pt**。行距按 1.35–1.5。字号一律取 `pptx_layouts.py` 的 `FS_*` 常量，**不要把 22/30 当 px 直接写进 DSL**（画布 1280×720px ↔ 幻灯片 960×540pt，1px = 0.75pt，写 22 会变成 16.5pt）。**每页眉题只写栏目名，不出现“模式 D / MODE D”**；封面与内页同样不显示该模式标记。排版仍须控制内容量：**双卡每卡 ≤4 行、整页要点 ≤5 条、单条尽量 ≤20 字**，放不下就拆页或删字，禁止通过进一步缩小字号硬塞。
3. **单边分隔线一律用独立的 1px 高 Box**，不要用对象式 `border: {bottom: …}`——渲染器会静默忽略，lint 也不报错。
4. 含装饰竖条的横向条状容器（说明条、引言条）**必须给显式高度**，否则整条塌陷、文字溢出框外（lint 只报 child-containment，不指名原因）。
5. 同排两卡内容行数不等时（如 3 行 vs 4 行）不要用双卡版式，改用"清单 + 结论卡"或上下分区，否则短的那张底部会空出 100px 以上。
6. **交替 ≠ 破连续**：深色左右互换、说明条上下互换、图左右互换都只是同一版式族内翻面（门禁只给 WARN）——破连续必须真的换族。
